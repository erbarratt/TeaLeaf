# CLAUDE.md

Guidance for Claude Code in this repository.

## Project overview

TeaLeaf: Thief-style VR stealth game, Unity 6000.3.25f1, URP, OpenXR + new Input System, **no XR Interaction Toolkit**. Keep it lean: add a package/third-party component only when clearly needed.

**Target: PCVR, 90 fps with 25% headroom at ~2000x2000 per eye on RTX 3060 12 GB, Ryzen 5 5600X-class 6-core, 16 GB RAM** = 8.3 ms/frame CPU and GPU each. That rig is the floor ("3060 upwards"); budget is measured against it, not the dev machine. Dev/test: Quest 3 via Virtual Desktop. **Quest 3 standalone is a future option, not a target**: nothing built for it, nothing may make a port impossible.

Movement, turning, gravity, crouch, climbing, ladders, ropes are all hand-built (control, debuggability, cross-headset consistency, understanding). **Never suggest XRI (or its locomotion, teleport, climb or interaction components).** No teleport locomotion, ever.

## Choosing a solution

- **Every solution is the simplest, most stable, most performant way.** Fewer moving parts, well-trodden over clever, cheaper at runtime; no unrequested options, layers or generality.
- **Where there are levels/options of complexity, stop and explain before building** (as for a question, no file changes): each option, its cost (build, maintain, runtime), what it gives, comparison, recommendation and why; then wait for the maintainer's choice. Applies when the three aims pull apart, when a request could be met at more than one scale, and when a third-party package is a route. One obvious simplest way: just build it.

## Coding standards

Follow for new code; flag (don't silently reformat) existing code that doesn't match.

- **Namespaces:** top-level only (`namespace Player { }`, never `Player.Locomotion`).
- **Serialized fields:** no underscore (`[SerializeField] private float moveSpeed;`). **Private non-serialized:** leading underscore (`_snapTurnQueued`), static readonly caches too (`_gripCurlParam`).
- **Public properties:** no underscore; prefer auto-property with private setter (`public Vector2 MoveAxis { get; private set; }`) over a passthrough expression body when the value should be cached/set elsewhere. Cheap derived values as expression bodies are fine (`IsLeftGrabbing => LeftGrip > 0.5f`).
- **Tooltips:** every serialized field (incl. fields of `[Serializable]` classes/structs) has a `[Tooltip]` on its own line above it: what it does, an example (`e.g. 0.5 = ...`), and for a number its units and what raising/lowering it does (bool: on and off; reference: what to assign, what empty does). Field comments stay as design notes.
- **Comments:** `/// <summary>` on methods; detailed inline comments encouraged (project is a teaching exercise: build new systems step-by-step with explanation, not a finished file at once). Never empty comment lines.
- **Braces (hybrid, keep consistent, don't unify):** control flow (`if`/`for`/`while`/`switch`) same line `if (x) {`; class/method/property declarations Allman (own line).
- **UI draws last, on top**, never hidden by world or hands (hand reticles, mantle arrow, markers). Materials via `OverlayMaterial.Create()` (`Scripts/Core`; shader `TeaLeaf/Overlay`: Overlay queue, `ZTest Always`, stereo-safe; a mark that fills like a meter uses `TeaLeaf/OverlayFill`, as the guards' alert marks), not depth-tested shaders; built-ins can't do this (see `Scripts/Player/CLAUDE.md`). Things held/worn on a hand (pack, compass) are objects, depth-tested like the hand.
- **Debug scripts:** always in a system `Debug` subfolder (`Scripts/Player/Debug`, `Scripts/Inventory/Debug`, `Scripts/AI/Debug`...), never beside runtime code.
- **Gizmos must show in the headset:** implement `IDebugDrawable`, draw through `DebugLines` (never `Gizmos` directly) so Scene view and headset (`InHeadsetGizmos`) share code; plain Gizmos show in one eye only. See `Scripts/Core/CLAUDE.md`; a new drawable type also gets a toggle in `InHeadsetGizmos` (`Scripts/Player/CLAUDE.md`).
- **Performance habits:** no per-frame allocations; cache `Animator.StringToHash`/`Shader.PropertyToID`; `MaterialPropertyBlock` not `.material`; touch renderers/materials only on state transitions; self-registering static lists/registries over scene searches or interface `GetComponent`.

### Performance rules

Design new systems, shaders, content and editor builders against these from the start. Say when a request breaks one and offer the cheaper route. Tasks: `Assets/DEVROADMAP.txt` ("Performance rules" block, Phases 6, 8, 10).

- **Budget 8.3 ms/frame CPU and GPU each on the target rig.** Nothing measured on such a machine yet: any cost is a judgement and must be called one.
- **Pixels are the biggest cost** (8M/frame x 90). Never *depend* on a full-screen/post effect or camera depth/opaque texture (an optional, switchable one is allowed once measured). No parallax occlusion on view-filling surfaces. Procedural surface shaders (cobblestone, brick, water) acceptable subject to measuring. Small transparent overdraw; UI/markers simple unlit shapes. 4x MSAA wanted (thin edges shimmer).
- **Shaders:** cheapest lit model that works; SRP Batcher compatible (`CBUFFER_START(UnityPerMaterial)`); single-pass-instanced stereo macros; per-vertex over per-pixel where it looks the same.
- **Lighting:** baked where possible, Adaptive Probe Volumes for movers and small pieces (read per pixel or vertex where it is, not one value per object; a lit custom shader includes URP's `ProbeVolumeVariants.hlsl`); few, short-range realtime lights. **Torches may cast realtime shadows from moving things** (guards, props, hands) with level shadows baked - Mixed lights, Shadowmask, Indirect Multiplier 0 so an extinguished torch leaves no baked glow (planned, untested) - as a switchable quality setting, never drawing the whole level into a torch shadow map. **Max four mixed lights overlap at any spot** (shadowmask limit; moon counts if Mixed).
- **Static level geometry**: Static, on `Environment`, few shared materials (batch, bake, occlusion-cull); editor builders making level/test geometry set this. Runtime-made renderers: shadow cast/receive off unless needed.
- **Depth is modelled, detail is textured:** shapes the player gets close to are real geometry; normal maps for fine detail only.
- **Layout culls:** break long sightlines with level shape and doors, plus an occlusion bake. **Generated buildings beyond full-detail range draw as one merged, lightmapped renderer, textured from one atlas per sector** (level generator's building proxies, `Assets/Scripts/LevelGen/CLAUDE.md`). Distance haze, nearer small-prop cull distances, textured impostors: reserves, only when profiling asks.
- **CPU work is sliced:** costly work (AI senses, pathfinding, light sampling, sound paths) a few times a second on staggered timers, never per frame, less when far/unseen. Physics queries non-allocating with their own `LayerMask`.
- **Nothing created/destroyed during play:** pool bolts, effects, audio voices; build runtime meshes/materials once at load.
- **Quest-port compatible:** all of the above except realtime torch shadows, optional post-processing and procedural shaders (a port drops or bakes those).

## Working with this codebase

- Unity project; no CLI build/lint/test, no automated tests. Builds and Play Mode via the Editor (exact version in `ProjectSettings/ProjectVersion.txt`).
- **Claude drives the open Editor via Unity's CLI** (`unity`, in user's `AppData/Local/Unity/bin`) + experimental editor-only `com.unity.pipeline` (in `Packages/manifest.json`): `unity status` (reachable?), `unity command recompile_status` / `console` / `save_scene`, `unity command eval --code '...'` (C# in the Editor; project `internal` types via reflection).
- **No scene is used, checked or suggested until the maintainer names it.** **Code, comments and docs never name a scene** unless what they describe is unique to it (mechanics work in every scene): code works on the open scene or takes a path, never a hard-coded scene path. After any level generator change, run it on the spec in use in the named scene (none named: ask) and save it (`Assets/Scripts/LevelGen/CLAUDE.md`).
- Root `.sln`/`.csproj` are Unity-generated; never hand-edit.
- All gameplay scripts compile into `Assembly-CSharp`; no `.asmdef` files.

**Git:** remote `origin` (GitHub), branch `master`. **One commit per session**, at the end, with the devlog/roadmap wrap-up, unless the maintainer asks sooner. Unity `.gitignore` excludes generated folders, `.csproj`/`.sln`, `.idea/`. Always commit `.meta` files with their assets. `Assets/Data/LevelGen/Proxies` (level generator's building proxy meshes and atlases) ignored: a fresh clone regenerates each generated level. `*.blend` (`Blends/`) ignored (exceed GitHub's 100 MB; need Git LFS to track). `Assets/ASTROFISH_GAMES` (bought art packs, 3.9 GB) ignored: a fresh clone re-imports from the Asset Store, converts materials to URP (Window > Rendering > Render Pipeline Converter, Material Upgrade), caps textures at 4096 in `STYLZ_MVillage` and 2048 in the other packs, turns Read/Write off on every pack model (meshes never read at runtime; readable = second copy in memory). Mesh compression stays off (saves nothing at runtime, can open seams between modular pieces).

## Architecture

### Frame ordering: explicit `Tick()` pattern

`PlayerController` (Player root) is the only player script with `Update()` (`PlayerHandAnimation` has the one `LateUpdate()`: finger poses over the Animator); it calls every player system's `Tick()`-style method explicitly for deterministic order. Sequencing and wiring only, no gameplay logic (decisions live in the owning system). Order:

1. `playerInput.Tick()` (first: caches input); `playerTracking.Tick()` (smooth hand poses; if headset recentred since last frame, put view upright and at standing height) - before anything reads head/hands. **Once the level has ended** (`LevelManager.StateChanged` -> not `Playing`; caught or won, during end fade) **frame stops here**, body frozen; only `playerHandInteraction.Tick()`, `playerHandDoors.TickHeld()`, `playerBow.TickHeld(false)`, `playerHandVisuals.Tick()`, `playerHandHolding.TickHeld()`, `playerHandThrowing.Tick(false)`, `playerArrows.TickFlight()`, `TickReticles()`, `playerHandAnimation.Tick()` run, so hands (and what they carry) follow the controllers.
2. `playerLocomotion.TickBody()` - re-centre capsule under headset, apply crouch height (before hand systems: crouch moves the tracked hierarchy).
3. `playerHandInteraction.Tick()` - hand rays + targets (reticles placed at 8b).
   3b. Reach-taken items, before the other grab systems (a hand taking one must already be busy when climbing/carrying/doors run); each skipped while mantling and if the rig lacks the component: `playerPack.TickSummon()` (bring pack out by a hand at the chest + grip, or put away on release); `playerLockpicking.Tick()` (take picks, put in lock, take hold of a pick on the big lock); `playerKeys.Tick()` (take keyring from pack, put in lock, take hold of key); `playerBlackjack.Tick()` (drawing over its shoulder); `playerArrows.TickPickup()` (pointing + grip on a lying arrow puts it back in the inventory) then `playerBow.Tick()` (drawing the bow over its shoulder, taking an arrow over the other, changing arrow kind). Where chest and shoulders are: `PlayerBodyZones` (no tick; asked).
4. `playerClimbing.Tick()` - grab/release, zip line, climb movement (skipped while mantling).
   4a. `playerHandHolding.Tick()` - pick up/drop props (skipped while mantling; after climbing, a hand grips a climbable or carries a prop); `playerPack.Tick()` - loot released at the pack goes in, items taken out (skipped without `PlayerPack`); `playerHandDoors.Tick()` - take/release door handles (skipped while mantling and without `PlayerHandDoors`; last of the three); `playerMantling.Tick()` - detect (arrow), start on stick push, or advance a mantle. **While `IsMantling` the frame stops here** (mantle positions the rig directly, CharacterController disabled): only `TickState()`, `playerVisibility.Tick()`, `playerKeyholes.Tick()`, `playerHandDoors.TickHeld()`, `playerBow.TickHeld(false)`, `playerHandVisuals.Tick()`, `playerHandHolding.TickHeld()`, `playerHandThrowing.Tick(false)`, `playerArrows.TickFlight()`, `TickReticles()`, `playerHandAnimation.Tick()` run - no locomotion, turning or `Move()`.
5. `_frameMovement = playerLocomotion.TickMovement(isClimbing)` (stick + gravity; zero while climbing) + `playerClimbing.FrameMovement` while climbing; then `playerLocomotion.TickTurning()`.
6. One `characterController.Move(_frameMovement)` (Unity calls `PlayerBodyPushing.OnControllerColliderHit()` during it: body pushes open doors), then `playerClimbing.ReportAppliedMovement()` while climbing.
7. `playerLocomotion.TickState(isClimbing, appliedMovement, collisionFlags)` - after `Move()`: needs real applied movement, returned `CollisionFlags` (stop momentum into walls/ceilings), and updated `isGrounded`.
   7b. `playerFootsteps.Tick(appliedMovement)` - after `TickState()` (needs this frame's `MovementState` + real movement); skipped without `PlayerFootsteps`, not run in a mantle or after level end.
   7c. `playerVisibility.Tick()` - after `TickState()`: samples light where the body ended up, applies `MovementState`; skipped without `PlayerVisibility`; runs in a mantle, not after level end.
   7d. `playerKeyholes.Tick()` - after `Move()`: keyhole near the head opens by final head position; skipped without `PlayerKeyholes`; runs in a mantle, not after level end.
8. `playerHandDoors.TickHeld()` - hand on a handle turns the lever and swings the door, after `Move()` and straight before visuals (hand then snapped onto the handle where the door now is). `playerLockpicking.TickHeld()` - hand on a pick turns it, big lock runs (pins), picking given up if the player moved away (runs wherever `playerHandDoors.TickHeld()` runs, every path). `playerKeys.TickHeld()` - key in a lock turned by the wrist; keyring returns to pack if player moved away (every path). `playerBow.TickHeld(canAim)` - arrow nocked, drawn (drawing hand snapped onto the string where the bow now is), shot on trigger release, arc (every path; `canAim` false in a mantle and after level end: nothing shot, an arrow let go returns to the inventory). `playerHandVisuals.Tick()` - after turning/`Move()`: visuals are rig children, so an earlier world-space snap pose would be dragged off, and the physical hand sweep needs the final controller position. (`TickHandVisuals()` runs the pair.)
   8a. `TickHeldProps()`: `playerHandHolding.TickHeld()` - once a visual reaches the prop being picked up, parent the prop to it (straight after visuals; skipped without `PlayerHandHolding`); a carried prop is a hand-visual child, nothing places it per frame. `playerHandThrowing.Tick(canAim)` - arc starts from the prop's current position (skipped without `PlayerHandThrowing`; `canAim` false in a mantle and after level end: nothing new aimed, a launch under way still finishes). `playerPack.TickHeld()`. `playerCompass.Tick()` - compass placed on the back of the wearing hand visual (every path; skipped without `PlayerCompass`). `playerArrows.TickFlight()` - arrows in flight, settling, noisemakers, ropes (every path, so a shot arrow flies on through a mantle; skipped without `PlayerBow`). `toolBurn.Tick()` - tools burning away or back in (every path; skipped without `ToolBurn`).
   8b. `playerHandInteraction.TickReticles()` - after grabs and visuals, so a hand that grabbed this frame hides its reticle.
9. `playerHandAnimation.Tick()` - last; reads this frame's snap weight from step 8 (Animators evaluate after all `Update()`s anyway); its `LateUpdate()` then lays each snapped hand's profile finger pose over the Animator's input curl.

New per-frame player systems get a `Tick()` (or `Tick...()` returning a movement contribution) and a slot in `PlayerController.Update()`. `PlayerController.Reset()` auto-fills references (root via `GetComponent`, hands via `GetComponentInChildren`).

**One `Move()` per frame:** `Update()` zeroes `_frameMovement`, adds each contribution, calls `characterController.Move()` once. New movement sources (ladders, knockback...) return/expose a contribution, never call `Move()`. Only exception: a mantle positions the rig directly. Everything in **`Update()`, not `FixedUpdate()`** (CharacterController and VR tracking want per-frame, lower latency).

- **A hand does one thing at a time** (climbing, carrying, door, lockpicks, keys, holding pack, blackjack, bow or an arrow for it): before taking a hand a system asks `PlayerHandState.IsBusyExcept()`, never checks other systems itself. New hand systems are added there once (`Assets/Scripts/Player/CLAUDE.md`).
- Body/movement systems on root, hand systems on `Hands`. `Hands` stays under `Camera Offset` with identity transform (tracked poses are relative to it; crouch moves `Camera Offset`).
- **Head re-updates before render; hands don't.** Main Camera TPD: "Update And Before Render"; hands' TPDs: **"Update"** only (before-render on hands made carried props lag). Don't switch back. World-fixed things (snapped hand, hand held off a wall) are detached from the controller.
- **Controller objects hold a smoothed pose:** `PlayerTracking.Tick()` overwrites the TPD pose with a One Euro filtered one (relies on hands' TPDs being "Update" only). Climbing uses it too; nothing reads raw tracking. Detail in `Assets/Scripts/Player/CLAUDE.md`.
- **Tracking:** XR tracking in **Device** mode (not floor); `Camera Offset` 1.6m gives every player the same standing eye height, real crouching still lowers it. `PlayerTracking` calibrates the view (`calibrateView`: flips an upside-down head, shifts to standing height) under the start fade and again on recentre (VD/SteamVR often start upside down with origin on the floor, so `Camera Offset` isn't always at its saved pose). TPDs read the project's `Tracking` action map (in `InputSystem_Actions`). Controllers bind the **pointer (aim) pose, not grip** - visuals, rays, snap offsets are tuned to it. Untracked controllers stay active holding last pose. Detail: `Assets/Scripts/Player/CLAUDE.md`.

### Physics layers

User layers 6-15: `Environment` (static world), `Player` (CharacterController, Player root), `PlayerHands` (Left/Right Hand), `Interactable` (grabbables, doors, loot, locks), `Climbable` (`ClimbableEdge`s, ladders, ropes), `Guard` (body capsule), `GuardHead` (blackjack target), `Projectile` (bolts), `PlayerBlocker` (invisible player-only boxes), `Ragdoll` (guard bone colliders: bolt hit boxes, the body when knocked out). Unassigned = `Default` (collides with everything).

Matrix pairs ON: Environment with Environment/Player/PlayerHands/Interactable/Guard/Projectile/Ragdoll; Player-Interactable; Player-Guard; PlayerHands-Interactable; Interactable with Interactable/Guard/Projectile/Ragdoll; Guard-Projectile; Projectile-Ragdoll; Ragdoll-Ragdoll; Player-PlayerBlocker. All else off (notably Player-PlayerHands, Player-Ragdoll (bodies walked through), Guard-Ragdoll, and Climbable with everything: it's a grab volume).

- **`PlayerBlocker` collides only with `Player`; no query mask includes it** (hands, props, bolts, guards, hand rays, light rays, guard sight pass through). New query masks must leave it out. Usage in `Assets/Scenes/CLAUDE.md`.
- **A carried prop moves to `PlayerHands`** (back on drop; also a hand-visual child) so the body doesn't hit it and hand rays, hand sweep and light rays ignore it.
- **Doors**: `Interactable` (leaf + handle trigger grab volume), kinematic Rigidbody turned from code; checks `Player` layer itself so it never swings into the body; body walking into an open door pushes it (`PlayerBodyPushing`).
- Matrix doesn't affect queries; each passes its own `LayerMask`: hand rays Environment + Interactable + Climbable (walls block); physical hand sweeps Environment + Interactable; light rays (`SceneLight`) Environment + Interactable (both block light); arrows (`PlayerArrows`) Default + Environment + Interactable + Ragdoll (limbs, never the `Guard` capsule).

### Vertical slice design (full plan: `Assets/DEVROADMAP.txt`)

Target: one docks/warehouse level - steal an objective, escape; caught = fail and restart.

- **Visibility:** from level geometry; only lights are hand-placed. Night levels: base light **moonlight**; a point is in full shadow when geometry blocks one physics ray towards the moon (gameplay shadows match rendered). **Light sources** (torches, lamps) add light in range, blocked likewise; extinguishing = disabling. Brightest light wins. Crouch/sprint modify: standing in moonlight is visible, crouching only from close. Shadow map not read back (too slow); rays stand in. No designer-placed shadow/light volumes.
- **Noise:** footsteps by surface (scaled by stance), thrown/dropped physics objects, doors/interactions - via a shared noise event system guards listen to.
- **Sound:** must tell the player truthfully where it is on stereo headphones. Thief-style designer-placed sound rooms joined by portals (doorways, stairwells); sound passes room to room only via portals, never through walls, heard from the last portal at the whole path's distance (a guard upstairs is heard from the stairwell or not at all). Closed doors muffle (high end rolled off). Guard hearing uses the same paths. No ray-cast muffling inside a room. **Reverb is the listener's room's, not the sound's**: one shared reverb tuned per `SoundRoom`. `SoundLoop`s and per-room ambience follow rooms. Direction from the project's own spatialiser (`SpatialVoice`: interaural time difference, head shadow, duller from behind; no up/down cue). No third-party audio package; Steam Audio is the fallback if up/down matters. Detail: `Assets/Scripts/Core/CLAUDE.md`.
- **Guard AI:** patrol -> suspicion -> search -> chase -> catch (no combat). Knockout state; **a knocked-out guard can always be woken by an awake one** that sees it and walks over. **A guard hit by a bolt that does nothing to it becomes suspicious and searches where it was shot from.** Built (`AI.Guard`, working in headset): Thief VR's two meters (suspicion, detection) and four vision zones with per-distance-band lit/dark fill times and movement multipliers (`AI.GuardSight` asset; lit/dark from player `Visibility`; five weighted points on the player), plus noises; baked NavMesh; looks a few times a second; **catches by diving at the player** (within catch range the dive starts and the catch is certain; `LevelManager.Caught()` as its hands arrive); **clip per action** (idle fidgets, wide look-around at each search place, hit front/back then dizzy when stunned, choking collapse from a sleep dart, push-up get-up after a knock-out); model prefab in `Assets/Prefabs/Actors` (Humanoid rig) animated by `GuardAnimation`; **head per state** (`AI.GuardHeadAim` from the `GuardHeadLook` asset: clip, straight ahead, or looking at stimulus/player; no rule = clip; sight follows the head); **alert mark over the head** (`AI.GuardAlertMarker`: question mark filling yellow with suspicion or detection, whichever is higher, red once suspicion is full, full yellow while searching, then draining away; exclamation mark red with detection; drawn on top of everything). Guards have their own `Update()`, outside the player tick order. **Voice lines don't repeat** (not built): large pools per voice, a session-wide record (kept across restarts) blocks repeats until a pool is exhausted; idle chatter is sound only, no noise event. Detail: `Assets/Scripts/AI/CLAUDE.md`.
- **Weapons:** blackjack and bow; no weapon menu. **Nobody dies (guard or player); every weapon is non-fatal**, and aggression towards guards is dissuaded. **Each hand reaches only over its own shoulder** (`PlayerBodyZones`): the lockpicks' hand's shoulder holds the bow, the other hand's the blackjack (right-handed: bow left shoulder, blackjack right).
  - **Blackjack** (`PlayerBlackjack`, `AI.Guard.TryKnockOut()`; built, working in headset): a leather-wrapped cudgel (Tripo model, `Assets/TripoModels/leather-wrapped_cudgel_3d_model`, 0.4m), drawn by the hand without the lockpicks, empty, reaching over its own shoulder and pressing grip; held while grip held; release puts it away (never dropped), and like the bow it burns into being when drawn and burns away where let go of (`ToolBurn`). **Head-to-head swing knocks out if the guard isn't chasing and the player is behind it**; otherwise the guard turns on the player.
  - **Bow** (`PlayerBow`, `PlayerArrows`, `ToolType.Bow`; built, working in headset; arrow kinds landing not yet tried): drawn over the lockpicks' hand's shoulder (grip), held in that hand while grip held. While it's held, the other hand reaching over its own shoulder takes an arrow of the chosen kind with the **trigger** (one taken from `PlayerInventory`), held while trigger held; brought within a sphere of the string's middle, arrow and hand snap onto it (nocked). The hand is then held, **in the string hand pose (position and rotation, not the controller's turn)**, to a straight line from the string's rest back a tunable maximum draw distance (direction `String_Rest` to `Draw_Full`; draw = fraction along it), the arrow pointing through `Arrow_Rest`. Releasing the trigger shoots; **the further drawn, the faster it leaves** (draw alone sets the speed, a real arrow's ~60 m/s at full draw); the arc appears only once the draw would shoot, fading in from there to full draw (at the arc colour's alpha), and is never shown as a bad shot. **No button cancels a shot**: easing the string back below a minimum draw makes letting go shoot nothing (arrow back to the inventory); below half draw, moving the drawing hand a tunable distance (15cm) off the line takes the arrow off the string, **still in the hand, no shot** (nocked again at the string); **from half draw on the hand stays locked on the string** until let back below half. **Letting go of an arrow not on the string returns it to the inventory** (never dropped in the world), as does **the bow hand letting go of the bow** (bow put away) while an arrow is held. **Bow and arrow let go of burn away** where they were let go of (an arrow shot or swapped for another kind doesn't), and **the bow burns into being when drawn** (`ToolBurn`, shader `TeaLeaf/Burn`; one tunable time 0-2s; detail `Assets/Scripts/Player/CLAUDE.md`). The bow hand's upper button (right-handed Y, left-handed B) moves on to the next arrow kind the player has (an arrow in hand is swapped) and does nothing else. Model (`Assets/TripoModels/bow_3d_model/bow_rigged.fbx`, built by `Blends/rig_bow.py` from the Tripo FBX): one mesh with a **`Drawn` blend shape** (limbs and two-segment string; weight = draw) and empties `String_Rest`, `Draw_Full`, `Arrow_Rest`; +Z the way it shoots; Rig None, no Animator (Unity then imports a plain `MeshRenderer`; `PlayerBow` moves the mesh onto a `SkinnedMeshRenderer` at load). **The game uses a handed copy, like a real bow: the arrow runs alongside the handle, touching it, never through it** - `bow_rigged_right_handed.fbx` (held in the left hand, handle right of the arrow) and its mirror `bow_rigged_left_handed.fbx`, chosen by `IsLeftHanded` (detail `Assets/Scripts/Player/CLAUDE.md`).
  - **Six arrow kinds** (`Inventory.BoltType`; built, `PlayerArrows`), each own Tripo model (`Assets/TripoModels/arrows_3d_model`), each shot uses one from `PlayerInventory`, **max three of each carried**: **water** (blue glass head) puts out every `Core.Flame` near where it lands; **noisemaker** (bells) makes noise where it lands for a while; **rope** (grapple wound with rope) hangs a climbable rope from where it sticks; **stun** (blunt metal head) on a guard's head stuns 10s, then it comes round and searches; **sleep dart** (green vial) hitting a guard anywhere makes it collapse 10s later (sinks down choking, then knocked out); **moss** (head overgrown with moss) lays a patch of moss on the floor where it lands (below it, off a wall) that makes the player's footsteps and landings on it **silent**, for the rest of the level (guards' steps unaffected). Water, noisemaker and moss are used up where they land. **The rest stick only into surfaces tagged as holding a bolt** (wood, plaster, carpet, grass) **and bounce off everything else**, guards included - a bounced bolt is a real physics object until it settles. **A stun bolt, or a sleep dart that hit no guard, is picked up** by pointing + grip: straight into inventory, never carried. Rope bolts never recovered; the rope bears weight only where the `SurfaceTag` has **Supports Rope Bolt** ticked - elsewhere it sticks but pulls out and the rope falls when the player takes hold.
- **Open flames can be put out, lamps can't:** torch/fire pit has a `Core.Flame` (switches gameplay light, visible light, flame and sound off together); lamp posts have none and burn on.
- **Chests** (`Interaction.Chest`, `ChestLid`): same lock kinds as doors (none, simple = pickable, keyed) via `PickableLock` / `KeyLock`. Once unlocked, a hand takes the lid front and lifts it.
- **Compass** (`PlayerCompass`; detail `Assets/Scripts/Player/CLAUDE.md`): **always worn on the back of the hand without the lockpicks**, where the picks sit on the other hand; read like a watch, no input, never makes its hand busy. World-aligned dial (**north = world +Z**), **light gem** showing `PlayerVisibility`, optional **arrows for the last few footsteps and voices heard** (switched off: `showSoundArrows`; never the player's own; no other sounds) pointing where heard from (the portal, for another room), sized by loudness, fading.
- **Text:** TextMeshPro (`com.unity.ugui`); font and shader in `Assets/TextMesh Pro` (TMP Essential Resources).
- **Controls:** left stick moves; right stick turns, up mantles, **down toggles crouch**; grip grabs; trigger aims a throw; **A jumps**; **B is the universal cancel** (aimed throw, for now; never the bow - while a left-handed player holds the bow, B changes arrow kind); bow, blackjack and pack gestures as above/below; **left stick click toggles sprint**; **left Y changes arrow kind** while a right-handed player holds the bow; X, Menu, right stick click unassigned. **PC Play** (dev switch on `LevelManager`, off for a build): Play Mode at the desk without headset - WASD walk, mouse look, Space jump, C crouch, Left Shift toggles sprint; movement only, hands ride under the camera (`PcPlay`, `Scripts/Player/Debug`).
- **Tools:** lockpicks only; no others planned. Two-handed lockpicking with haptics (built: `PlayerLockpicking`, `Interaction.BigLock`, `PickableLock`): two picks (Tripo model `Assets/TripoModels/lockpicks`: a hook and a tension wrench) worn on the back of the left hand go into a simple lock's keyhole and burn away; **large copies of the two picks burn into being sticking out of the real keyhole** (`ToolBurn`, like the bow; no copy of the lock is drawn) and burn away there when the picking ends (walked away, or opened); right hand turns one pick clockwise through three stops and a last turn while the left sweeps the other to find each stop's random pin by haptics; a pick is turned by moving the hand round the keyhole, not twisting the wrist. Detail: `Assets/Scripts/Interaction/CLAUDE.md`, `Assets/Scripts/Player/CLAUDE.md`.
- **Inventory** (all built; `Assets/Scripts/Inventory/CLAUDE.md`): backpack of limited size, so the player keeps the most valuable loot. **Brought out by either hand at the chest, palm towards it, + grip**; an open chest (Tripo model) held by the handle on its end, handle on the holding hand's side, spaces inside always the right way round; rides on that hand while grip held, release puts it away; the other hand puts loot in: 3x3 grid, one loot per space, chosen by holding loot over a free space; a gold space for small loot; separate spaces for objective and keyring. Carried loot shows one to three coins for worth. Coloured keys on the keyring, taken from the pack and held to a lock. **One coin level = one gold piece** (loot worth 1-3 gold); pack gold shown as a number (TextMeshPro). **Handedness** is one setting, `PlayerInputXR.leftHanded` (read as `IsLeftHanded`): off = lockpicks and bow left, compass and blackjack right; on = swapped. Pack and keyring work in either hand; the lock puzzle is never mirrored.
- **Throwing, aimed and physical** (both built: `PlayerHandThrowing`, `PlayerHandHolding`; detail `Assets/Scripts/Player/CLAUDE.md`). Grip picks up. Aimed: hold that hand's trigger for a trajectory arc (distance from hand pitch, teleport-arc style); release plays a short hand launch (forward move of the visual, not a clip) and throws along the arc. **B cancels** (prop stays in hand); an arc landing on nothing is red and releasing throws nothing. Physical: move the hand and release grip to throw with the hand's movement; a still hand just drops.
- **Traversal:** sprint, jump, mantling, ladders, rope climbing (built); drag/hide KO'd bodies (with the guards).
- **Physical hands:** visual hand collides with the world, stops at surfaces, elastic-bands back to the controller once clear (Alyx / Thief VR); kinematic sweep, no Rigidbody. **Shape: six pieces per hand** (palm box, thumb and finger capsules) fitted from the bones, fingers switching between open and fist with trigger/grip; a carried prop adds its own colliders, so hand and prop both stop.
- **Sky:** no skybox; camera clears to black; `Core.ProceduralSky` draws steady stars, the moon (a photo on a disc where the Directional Light shines from) and Thief VR-style drifting clouds (a cubemap) over them. Picture only, lights nothing. **Moon shafts** are `Core.GodRayBox`es (shader `TeaLeaf/GodRayBox`): placed geometry, never a screen effect or real volumetric light; the generator puts one beside each building casting a moon shadow onto a street (found by physics rays), from the street up the moonlight to above the roofs; others hand-placed. Not yet judged in headset. Detail: `Assets/Scripts/Core/CLAUDE.md`.
- **Art:** slice must look like a finished game, not greybox.
